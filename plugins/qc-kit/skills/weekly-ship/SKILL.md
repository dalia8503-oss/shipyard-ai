요청: $ARGUMENTS

0. 대상 주가 비었거나, 추적 중인 파일에 커밋하지 않은 변경이 있으면 시작하지 않고 사람에게 묻는다. 추적하지 않는 새 파일은 상관하지 않는다.
   원본 위치는 `C:\work\labs\현업미션\data-셋째주\`(저장소 밖, 읽기 전용)이다. 에이전트에게 이 경로를 명시해 넘긴다. `의장팀_검사기록_ERP.csv`는 CLAUDE.md의 원본 3개가 아니므로 집계하지 않는다.
1. qc-aggregator에게 집계를 맡긴다. 쓰기는 `out/` 에만 허용한다.
   DFT 후보 처리 방침 등 미결 사항은 `out/미결사항.md`에 남기게 하고, 결정은 사람에게 묻는다(임의로 정하지 않는다).
2. qc-auditor로 조립/선각/도장 원본별 독립 검증을 동시에 돌린다. 요약본과 불일치하면 지적 사항을 3단계 반려와 같은 방식으로 qc-aggregator에게 돌려보낸다(회차에 포함).
3. 검증이 일치하면 qc-writer에게 `out/회의문장.md`(회의 문장 세 줄, 숫자마다 출처)를 쓰게 한다.
4. reviewer에게 git diff, qc-auditor 결과, `out/회의문장.md`를 넘기고 판정을 `out/review.md`에 저장한다.
   reviewer의 반려 기준을 바꾸거나 빼라고 지시하지 않는다.
5. 반려면 지적 사항만 담당 에이전트(집계 문제는 qc-aggregator, 문장 문제는 qc-writer)에게 다시 넘기고, 고친 뒤 2~4단계를 다시 돈다. **반려 처리는 최대 2회**다.
   반려 사유가 집계 기준(CLAUDE.md 규칙이나 미결 사항) 변경 때문이면 스스로 고치지 않고 사람에게 묻고 멈춘다.
   2회 뒤에도 반려면 남은 지적을 보여 주고 멈춘다.
6. 통과하면 `out/회의문장.md`와 변경 요약을 보여 주고 멈춘다. push는 하지 않는다.

review.md에는 회차마다 판정, 대상(git diff 범위), 원본 대조 결과(일치/불일치 건수)를 남긴다. 덮어쓰지 않고 아래에 더한다.
검증 보고에는 확인하지 못한 항목(그래프, 합계 행 등)을 반드시 포함한다.
